# 项目协作规则

先阅读 PROJECT.md、任务明确列出的输入文件，再按需读取源码与数据。

1. 当前仓库是协作启动示例。迁入真实项目时，保留原有 AGENTS.md 并合并必要规则，不直接覆盖。
2. 以当前任务 JSON 为范围与验收约定。只修改 allowed_paths 内文件，不擅自扩大目标。
3. Core、Range、义项、词性、音节与去重口径存在歧义时，列出具体问题；不静默换定义。
4. data/raw/ 保存原始材料。派生数据放到 data/processed/ 并记录来源、版本和生成方法。
5. 不擅自改变 schemas/；结构性建议先写成提案，由用户决定是否采用。
6. automation/ 是调度与验收代码，执行任务不能更改。不得通过削弱测试来制造通过结果。
7. 调度运行中不执行 Git commit、checkout、merge、push，不启动额外代理。提交和状态由调度脚本维护。
8. 事实、模型推断、实际执行结果要分开写。没有实际运行检查就不能声称检查通过。
9. 需要交接时写清输入版本、产出路径、验证证据、未解决问题，不依赖其他会话的隐含记忆。
10. runtime/ 的状态文件不由执行者修改。审阅者只读检查，不兼任本轮执行者。
