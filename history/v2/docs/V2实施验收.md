# V2 实施顺序与验收清单

本清单落实 [V2设计方案](V2设计方案.md) 和 [V2协议与恢复](V2协议与恢复.md)。基线为 integration 的 `f167f4178baf5b33c31dca4fea6e4157aa893426`。下列阶段尚未完成，不以历史 CI 或演示截图代替本次实现证据。

## 1. 开发方式

沿用独立 V2 目录和唯一活跃 React 前端。每个阶段从核对后的开发基线创建小分支；存在未合并依赖时明确 stacked base，不能把设计分支或旧原型默认为 main 已具备的能力。V1 源码、安装、runtime、历史证据不在这些阶段的修改范围。

每阶段都要能单独演示和回退。只有触及行为的阶段新增对应测试；文档变更检查链接、协议一致性和差异即可。Linux 进程/锁测试必须在 Linux 运行，Windows 跳过不算完成。

## 2. 实施阶段

| 阶段 | 交付 | 主要修改位置 | 通过后能做什么 |
| --- | --- | --- | --- |
| M0 手机入口验证 | 实际手机 Chat 创建普通 Issue、评论、回读及作者身份验证 | Chat/GitHub 接入说明与非执行测试 Issue | 确认远程入口确有写能力，不能仅凭桌面工具推断 |
| M1 协议与事务基础 | V2 独立前缀、严格解码、Host/请求/仓库身份、SQLite 事务和显式迁移 | github_protocol、contract、control、claim，新增 store | 指令可安全登记、去重、恢复，V1 不会领取 V2 指令 |
| M2 真实执行与过程记录 | Codex 执行/独立审阅、精确 JSONL 分类、预算、进程组清理、持久化事件 | codex_adapter、controller、evidence，新增 supervisor/runner | 一个本地合同能真实执行并完整回看，暂不远程自动接单 |
| M3 GitHub 完整闭环 | 普通任务拉取、控制优先通道、候选发布、outbox、人工 merge 后核对 | gh_cli、git_workspace，新增 publisher/daemon | 手机经 Chat 派单，本机只领取一次并交付 PR |
| M4 本地工作台 | 真实 API/SSE、快照续传、任务过程、检查/文件/PR、暂停/取消、模式隔离 | 本地 API、web/app/api-client、useWorkspace、任务页面 | 关掉再打开页面仍能看过程，断线不出现假在线 |

## 3. 每阶段的关键测试

### M0

- 在实际手机 Chat 与目标账号上验证读仓库、创建普通 Issue、添加普通 Issue 评论、完整回读；测试标题不用任何执行前缀。
- 创建或评论响应不明时能先回查；普通 Issue 与 PR 评论能力分别确认。
- 无写权限时准确报错；接入可写连接器后再验收，不宣称手工粘贴等价于 Chat 自动发布。

### M1

- 旧 V1 标记和 V2 原型旧标记不被新生产入口领取；V1 原码面对新 V2 标记保持忽略。
- 授权作者、目标 Host、仓库 ID、Issue/评论 ID、期限、基线、策略哈希逐项不匹配时拒绝。
- 重复 JSON 键、未知字段、路径穿越、超大正文、布尔值冒充数字、非法 Unicode/类型均有明确行为。
- 同 request_id 同载荷复用记录；同 ID 不同载荷冲突；不同仓库相同 GH-N 互不污染。
- 崩溃注入覆盖状态/事件/outbox 的事务边界；任何重启都不会只看到“状态已改但无回执事实”。
- 旧 JSON schema、完整备份、迁移重复运行、迁移中断、无历史回执证据、坏数据都保持防重放。

### M2

- `item.completed` 不结束任务；真正 turn 成功但进程非零、退出零但结果缺失、损坏/未知事件均不误报成功。
- stdout/stderr 同时大量输出不死锁；长行、日志限额、磁盘满可收敛且不丢关键状态。
- 执行/检查/审阅超时可终止所属进程组；grandchild 不残留；其他无关进程不被误杀。
- 取消、进程退出和检查开始的竞争有确定结果；清理未确认前执行槽不释放。
- 空工作区探测的 Git 前置条件明确；CLI 版本/模型/effort 不支持时不静默替换。
- 路径检查包括新文件、重命名、删除、symlink、Git 元数据；审阅者不能改候选。
- 凭据、主机 runtime 和不允许读取的路径用实际隔离测试验证，不只检查参数字符串。

### M3

- 超过一页 Issue/评论、分页间更新、重复抓取、关闭/重开、授权删除，均不漏查已知活跃任务或误启动。
- ETag 304、401、403/429、Retry-After、5xx 和断网遵守退避；不把权限失败当成没有任务。
- 长时间模型运行时 pause/cancel/status 仍能及时入库和处理，旧回执失败不堵取消。
- 模型设置探测与任务共用唯一执行槽；设置 pending 时取消照常响应，revision 冲突不会覆盖新配置。
- push 成功响应丢失、PR 成功响应丢失、回执成功响应丢失只核对/补发，不新建执行 attempt。
- 任务运行前及发布前 main 前进时停在 stale_base，不用旧检查包装新候选。
- 同仓库待审阻止后续写任务；另一仓库可取得唯一执行槽。
- 原候选 merge commit 可以核对 accepted；squash/rebase 或同步冲突明确待人工处理。

### M4

- 首屏来自真实快照，unknown/null 与空列表不以 fixture 填补。
- 快照到订阅期间出现新事件不丢失；重复事件去重；断线补齐；过期游标重取快照。
- 跨仓库同号任务、同任务多次 attempt 与迟到旧响应不串页、不覆盖新状态。
- 本地 API 有会话、Host/Origin/CSRF 校验；证据路径穿越与输出脚本不能执行。
- 模型设置 pending/失败/冲突保留表单草稿；实际 applied 后才更新确认值。
- 取消页面文案区分 requested 与 stopped；PR 已创建不能显示为“所有操作已撤回”。
- 在桌面及 390/320 像素宽度检验导航、键盘、对比度和溢出；上千事件仍可回看。
- 明确测试 Mock、local-smoke、真实 Host 三种模式；真实连接出错不隐式 fallback。

### M5

- 关闭全部终端和浏览器后，手机发任务仍可领取；记录 WSL/Windows/CLI 版本及实际设置。
- Windows 锁屏、代理失效、断网恢复、WSL 停止/重启、Windows 重启后行为符合设计。
- Windows 睡眠时不宣称正在接单；恢复后过期任务不自动执行。
- 服务只运行一个实例；后台重启先恢复现场和清理，不自动重跑上次模型。
- 一致性备份可还原任务和去重事实；回退到 V1 不覆盖 V2 现场，也不混用两套队列。

## 4. 最小真实验收任务

选择一个用户明确登记的测试仓库，不默认使用本工具库。在手机 Chat 发布只改一份文档的小任务，固定基线、允许路径、一个真实项目检查和交接要求。

必须取得以下证据：真实 Issue 与唯一授权评论；主机领取记录与同一 run_id；CLI 版本、冻结合同、具体模型配置、执行事件；固定检查与独立审阅；精确候选 SHA、真实 PR；工作台重开后的历史；人工 merge 后的远端与本地核对。

另用隔离测试注入断网、回执响应丢失和服务重启，不在有未备份工作时直接断电。证明通信恢复不新增模型 attempt；中断执行进入明确待处理，而不是无人确认地继续。

设计验收目标：正常联网且未限流时，指令在约两个配置轮询周期内被观察；本地已持久化事件在正常负载下约两秒内可见；真实运行取消后约十五秒内完成进程清理或明确显示未清理完成。以上是待实测目标，不是现有系统性能承诺。

## 5. 与现有证据的关系

当前 integration 的 Python CI 成功只覆盖其实际测试、示例和安装入口。已有 local-smoke 证明的是本地 HTTP/core 与确定性替身联调。已有 React 截图证明的是对应模拟页面。它们都不证明完整远程任务链、无人值守常驻或真实模型长期稳定性。

本轮设计变更仅增加本组文档、入口链接和示例工作台预览。运行源码、V1、现用配置与用户现场均未修改；新的协议、状态库和进程监督须按上述阶段实施后再逐项声明完成。
