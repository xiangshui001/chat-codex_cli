# 用户使用手册：MVP-2

当前 V2 0.1.0 支持指定新/旧对话、三种模型模式、Host 路由、本地成果与草稿 PR。首次部署请先读[安装说明](安装说明.md)或下载[离线 HTML 指南](使用指南.html)。旧版本资料在 history 中归档。

## 安装与启动

1. 在本机 Ubuntu / WSL 安装并登录 GitHub CLI 与 Codex CLI，获取工具源码。
2. 按 [MVP-2 安装说明](V2-MVP2.md)创建新虚拟环境、本机私有配置和新状态/工作区目录。owner 填本人账号；每台电脑使用不同 host_id，例如 `desktop` 或 `laptop`；hub_repo 填本人记录仓库。
3. 先用 `--list-repos` 检查发现范围，再启动 `codex-github-local-v2 --config /ABS/PRIVATE/config.json`。
4. 其它 API 模型在本机 models.json 登记 provider、接口、型号、思考参数与密钥环境变量名。密钥由进程环境提供；只用 GPT CLI 时允许空 providers。
5. 构建 `web/app`，使用 `codex-github-local-v2-workbench --protocol mvp2 --config ... --dist ... --port 8791` 启动只读工作台。浏览器打开 **http://127.0.0.1:8791/**。

监听器和工作台是两个进程；关闭浏览器不会停止任务。持续监听可由本机进程管理器维护；程序本身不安装 Windows 开机/唤醒服务。WSL 必须正在运行，不能假定关机后继续执行。

私有 config.json 的 `max_parallel_tasks` 控制同时执行的任务数，新安装示例为 3，可设 1–16；省略为 1。每个任务有独立执行进程、目录与分支；同一旧对话的续接依次执行。名额满时其余 Issue 等待下一轮检查。已有安装按[并发升级步骤](V2-MVP2.md#并发配置与升级)备份并显式迁移执行状态，不能在当前任务运行时升级。

## 发布与续接

把 [Chat 协作手册](Chat协作手册.md)交给 Chat，提供目标仓库、机器标识、任务和允许修改路径。Issue 可发在目标仓库，或配置的本机记录仓库；必须包含匹配的 host_id 和目标默认分支完整 SHA。

新对话选择 `session.mode: new`；续接选择 `session.mode: resume` 并提供回执中的 session_id。GPT 对话必须存在于执行机；其它 API 对话使用本机消息历史。续接上下文不自动带入旧任务未合并的文件，新工作区仍从本次基线开始。

API 回复截断或为空时会保留上下文继续请求，工作台显示恢复原因，不再立即失败；截断的工具指令不会执行。已有失败 API 任务需用户明确要求恢复，再按[恢复步骤](V2-MVP2.md#api-不完整回复与失败会话恢复)找回会话，并发布新的续接任务，保留旧记录。

三种 models.mode：`gpt`（指定 GPT 型号和思考强度）、`api`（只用登记的其它 API 模型）、`gpt-led`（GPT 主导并按需调用登记的其它模型）。完整 JSON 见 [MVP-2 协议](V2-MVP2.md)。型号可用性依赖实际账号；思考强度应在本机映射中明确配置。

## 查看成果

工作台顶部明确显示当前有没有任务、最近完成 GitHub 检查的时间、下次检查时间和本轮仓库检查进度。页面刷新时间只代表读到了本机记录，不代表刚检查了 GitHub。监听进程运行也不代表模型正在执行。

未通过领取检查的 Issue 会显示链接与原因，例如模型名未登记、思考强度不支持或缺少本机密钥；其它电脑的任务不会列为异常。模型名需按本机登记值精确填写，包括大小写，思考强度必须在本机 effort_map 中登记。工作台不擅自替换模型或降档。

当前任务显示模型、已用时间和最近活动，可一键打开任务详情。API 模式显示等待模型回复的轮数及文件操作；等待期间没有新输出也会持续更新时间。工作台继续展示本地领取的任务、对话 ID、输出、文件变化、PR 和原 Issue 回执。成功任务保留本地目录，同时提交专用分支和草稿 PR；**人工审查后合并**。没有文件变化时回执明确说明不创建空 PR。

PR 发布或回执网络失败会保留进度，只补做外部发布。执行中断、清理不确定或 commit 不确定时停止接单，先核对已有进程和文件；不要删除数据库或复用 request_id。stale_base 需要重新检查最新基线并发布新授权。

## 模型协作 API

启动 `codex-github-local-v2-model-api --models-file ... --port 8792`，设置本机随机令牌 CODEX_COLLABORATION_TOKEN，每次请求带 Bearer 认证。POST /v1/respond 支持同样三种文本协作模式，HTTP 的 GPT 模式使用登记的 OpenAI provider 和 API key；不会修改仓库。接口见 [API 说明](V2-MVP2.md#本机-http-api)。

验证范围和实际结果见 [VALIDATION](VALIDATION.md)。本电脑的验证结论不能替代其它电脑的独立验收。
