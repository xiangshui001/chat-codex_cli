# 用户使用手册：MVP-1 与真实工作台

本文对应当前 V2 0.0.6。现役 V1 用户请看 [V1 使用手册](v1/用户使用手册.md)，两套协议和状态目录不能混用。

## 安装与启动

1. 在执行电脑的 Ubuntu / WSL 安装并登录 GitHub CLI 与 Codex CLI，获取本工具仓库。
2. 按 [MVP-1 安装与配置](V2-MVP1.md)创建独立虚拟环境和本机私有配置，设置 owner、host_id、workspace_root 和 state_dir。
3. 先用 `--list-repos` 查看可访问的本人仓库，再启动持续轮询的 `codex-github-local-v2-mvp1 --config /ABS/PRIVATE/mvp1-config.json`。
4. 按[工作台安装说明](MVP1-WORKBENCH.md)构建前端，另行启动只读服务，配置指向同一份 MVP-1 配置。
5. Windows 浏览器打开 **http://127.0.0.1:8791/**。两个服务都要保持运行；工作台不会代替你启动监听。

端口 5173 是前端开发服务器，默认也是真实工作台，需要 8791 后端。`?view=demo` 才是旧演示页面；演示不能证明 Codex 实际执行。

## 派单与看结果

把[Chat 协作手册](Chat协作手册.md)交给 Chat，并提供目标仓库、登记的 host_id、任务要求和允许修改的相对路径。本人仓库由程序自动发现；Chat 和执行端各自的 GitHub 授权都必须能访问目标仓库，新仓库先创建初始提交。

Chat 创建 `[codex-v2-mvp1]` Issue 和唯一授权评论。监听器每轮完成后约等待 60 秒；已有任务执行时新任务等待。工作台每约 3 秒刷新已经领取的本地任务，展示领取、执行、结束和回执；尚未领取的 Issue 暂不显示。

结果保存在工作台所示任务目录。检查文件变化后，再决定提交、推送和合并。下一任务不会继承上一次未提交修改。关闭浏览器不取消任务，关闭工作台服务也不停止监听。

## 遇到问题

- 页面连接失败：检查只读服务、端口和配置；旧数据会明确标记过期，不切换成演示数据。
- Issue 未领取：核对两个 GitHub 授权、owner、Host、标题和授权协议，并查看监听错误。
- `stale_base`：发布时默认分支基线已变化；先确认最新状态，再通过新 Issue / 新 request_id 明确重新授权，不能修改旧任务绕过校验。
- 重启发现未完成任务：先人工核对进程与成果；不要删除数据库或重复派发同一任务。

本机不包含开机自启或完整恢复服务。台式机 WSL 必须独立验收，不能直接套用本电脑验证结论。
