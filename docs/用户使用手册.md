# 用户使用手册：手机远程使用

V2 0.2.1 支持手机派单、同一个 Issue 持续对话和远程恢复。首次部署见[安装说明](安装说明.md)，离线说明见[HTML 指南](使用指南.html)。电脑须开机联网、运行监听器；Windows 使用 WSL。

## 日常使用

在工作仓库新建 Issue，正文填：

```text
/codex run desktop
model: gpt-6.1-sol
effort: high
paths: .

写清你要做的任务，完成后保存成果并提交 PR。
```

desktop 换成目标机器的唯一 host_id。整仓修改填 `.`；只写报告可填 `docs/review-report.md`，读取审查范围仍是整个仓库。无需自己准备 SHA 和任务编号。记录仓库派单加 `repo: OWNER/PROJECT`。三种模型与可选字段见[协议](V2-MVP2.md)。

领取后 Issue 会收到机器确认；默认每 15 分钟更新一次进度。运行几小时后继续留言即可加入原对话。单独留言 `/codex status` 或“进度”会回复当前阶段，无需回到电脑。完成或失败后留言 `/codex retry` 从保留的现场继续，也可直接追加下一步任务。

`/codex allow .` 扩大整仓修改权限，`/codex stop` 停止并保留现场，`/codex merge` 合并当前成果 PR。未领取的错误会回写 Issue，可以修改手机派单正文；已领取任务的新要求写新评论。

## 长任务

默认没有程序设置的时间、数据、日志、上下文、回复轮数或 API 调用次数上限。已有私有配置若仍填有限值，设为 null 并重启服务。API 能分页列文件、分段/完整读写大文件、追加写入、处理二进制、执行命令和测试。完整命令输出落盘，预览分页不会终止任务。

不完整回复、网络断开、429/5xx 自动退避恢复；服务拒绝会保留现场等待，同时在 Issue 提示接口问题。服务商的额度/上下文容量与本机磁盘、网络仍影响执行。明确停止和内容过滤会结束当前轮。

## 多电脑与成果

每台电脑独立配置 owner、唯一 host_id、私有路径和模型。新安装示例同时处理 3 个不同对话，可用正整数调整并发。同一会话串行，后续指示不会丢弃。监听本人账号全部可见仓库，任务可发在目标仓库或本机 hub_repo。

成果保存在原工作目录，提交分支、创建 PR、回写原 Issue。完成后在同一 Issue 继续，会复用原对话和文件，更新成果 PR。模型执行完成但发布失败时自动补做发布，main 有其它电脑的新提交不会仅因基线变化而阻止 PR。

协作模型返回的 job_id 可在原任务续跑时继续查询，完整结果保留在本机。若旧进程中断且调用结果无法确认，会明确显示未知状态；已保存的完成结果不会因此重新调用。

工作台 http://127.0.0.1:8791/ 显示实时活动，仅本机直接可用；手机通过 GitHub Issue 查看即可。新引擎的重启恢复会验证进程归属并清理遗留进程，避免重复执行；升级前的未知旧现场只暂停自身，通过原 Issue 明确续跑，不堵其它任务。

## 升级

已有 0.1.0 安装按照[升级步骤](V2-MVP2.md#并发配置与升级)备份并迁移 schema 3/4 → 5，保留数据库、会话和本地文件。不要删除旧状态重新开始。安装器/验证范围详见[VALIDATION](VALIDATION.md)。
