01

这次版本实现了什么

从 GitHub 派单，到电脑执行，再到成果交付。

对话上下文

新建或继续指定旧对话

新任务可创建 Codex CLI 对话，也可用明确 UUID 续接本机旧对话；回执和工作台显示会话 ID。其它 API 模型保留自己的本机消息历史。

模型协作

三种模式，型号与思考强度可选

独立目录保存文件，检查通过后提交分支和草稿 PR，并回写原 Issue。无文件改动时不创建空 PR，合并由用户审查决定。

第一次安装与日常使用

各电脑独立安装；已有当前版本的用户可直接跳到第 03 节。

执行端已验证 Linux / Ubuntu / WSL。Windows 用户在 WSL 中运行；原生 Windows 与 macOS 执行端尚未验收。Chat 的 GitHub 连接与本机 gh 是两套凭据，需要同一 owner 且都能访问任务仓库。

输入唯一机器标识，如 desktop、laptop 或 office-pc。同一账号的各电脑必须不同。脚本生成私有配置、空模型表与随机 API 令牌，不覆盖已有文件。

Linux / WSL · Bash

python3 - "$run_dir" "$account_owner" "$machine_id" <<'PY'
import json, os, re, secrets, sys
from pathlib import Path
root = Path(sys.argv[1]).expanduser().resolve()
owner, host = sys.argv[2].lower(), sys.argv[3]
if not re.fullmatch(r"[A-Za-z0-9][A-Za-z0-9-]{0,38}", owner):
    raise SystemExit("账号格式不正确")
if not re.fullmatch(r"[A-Za-z0-9][A-Za-z0-9_-]{0,63}", host):
    raise SystemExit("机器标识使用字母、数字、下划线或短横线，最长 64 位")
root.mkdir(parents=True, exist_ok=True, mode=0o700)
config = {
    "owner": owner, "host_id": host, "hub_repo": owner + "/codex-cli",
    "workspace_root": str(root / "workspaces"),
    "state_dir": str(root / "state"),
    "models_file": str(root / "models.json"),
    "poll_seconds": 60, "timeout_seconds": 900
}
files = {
    "config.json": json.dumps(config, ensure_ascii=False, indent=2) + "\n",
    "models.json": '{"providers": {}}\n',
    "service.env": "CODEX_COLLABORATION_TOKEN=" + secrets.token_urlsafe(48) + "\n"
}
if any((root / name).exists() for name in files):
    raise SystemExit("已有配置，请保留并手工核对；没有覆盖文件")
for name, content in files.items():
    fd = os.open(root / name, os.O_WRONLY | os.O_CREAT | os.O_EXCL, 0o600)
    with os.fdopen(fd, "w", encoding="utf-8") as stream:
        stream.write(content)
print("配置已保存到", root, "；令牌保存在私有 service.env 中")
PY

04

怎样继续旧对话

保留讨论上下文，下一次任务使用本轮的工作目录与授权。

  1. 从上一轮 Issue 完成回执复制 session_id，或点开工作台任务查看会话 ID。
  2. 下一轮使用同一个目标仓库和本机执行端。在第 03 节选择“继续旧对话”，粘贴完整 UUID。
  3. 新任务仍可选择型号与强度。GPT CLI 对话使用 codex；其它 API 对话继续使用原来的 provider。
  4. 发布新的 Issue、新的 request_id，完成后检查回执中的会话 ID。

保留下来：对话里的讨论

前面说过的需求、分析与上下文可以继续使用。续接从上轮回执中的明确会话 ID 读取本机上下文。

本轮代码：从当前默认分支开始

每次任务使用独立克隆。需要基于旧改动继续做时，先审查并合并旧 PR，再发布新任务；未合并文件不会自动带入。

这里的 ID 是执行端 Codex CLI 或 API 执行器的对话 ID，直接来源是任务回执和工作台。当前 Chat 页面的聊天不会自动成为执行端会话。
已有更早的 Codex CLI 对话可以导入吗？

可以，但 UUID 对应会话文件必须存在于运行监听器的系统用户的 Codex 会话目录，而且原工作目录的 Git origin 要与本次目标仓库一致。找不到或来源不匹配时拒绝续接。

会话必须属于实际运行监听器的同一系统用户。仅存在于其它用户、其它电脑或 Windows 端的历史文件，需要先核对执行端是否能识别，不能只凭页面显示的 ID 假定可用。

05

接入自己的其它模型

只用 GPT CLI 可以保留空 providers；其它 API 和 GPT 主导需要登记模型。

  1. 准备 OpenAI 兼容接口的地址、准确型号与 API key。按服务商文档核对 Chat Completions 或 Responses 协议。
  2. 编辑私有运行目录中的 models.json。以下示例用 other 作为登记名，替换域名和 OTHER_MODEL；有其它 provider 时保留已有条目。
  3. 在同目录 service.env 填写密钥变量。任务 Issue 只填 provider、model 和 effort，不放密钥、地址或环境设置。
  4. 等待监听器空闲后，结束并按第 02 节重新启动监听器和 HTTP API，加载新配置。
models.json · 替换接口和准确型号
{
  "providers": {
    "other": {
      "kind": "other",
      "base_url": "https://PROVIDER.example/v1",
      "api_key_env": "OTHER_MODEL_API_KEY",
      "wire_api": "chat_completions",
      "models": [
        "OTHER_MODEL"
      ],
      "reasoning_parameter": "reasoning_effort",
      "effort_map": {
        "low": "low",
        "medium": "medium",
        "high": "high"
      }
    }
  },
  "max_turns": 40,
  "max_calls": 8,
  "request_timeout": 120,
  "max_output_tokens": 8192
}
service.env · 本机填写，遵循 Bash 引号规则
OTHER_MODEL_API_KEY='在本机填真实密钥'
# 保留已生成的 CODEX_COLLABORATION_TOKEN
配置项怎样填写
wire_apichat_completions 或 responses，按服务商接口选择。
reasoning_parameter服务商实际使用的思考参数，如 reasoning_effort 或 reasoning.effort。
effort_map把任务中的 low / medium / high 等映射为实际参数值；明确映射为 null 表示不发送该参数。
models只登记实际可调用的型号。派单型号必须在此表中。
api_key_env保存密钥环境变量名，实际值由运行进程环境提供。
GPT 主导时，其它模型只获得 GPT 提交的问题并返回建议；GPT 决定如何使用结果。其它 API 单独执行仅提供受授权路径约束的文件工具，不提供任意 shell，生成文件不代表已运行项目测试。

独立 HTTP GPT 需要 kind:gpt 的 OpenAI provider 和独立 API key；Codex CLI 登录不能代替该 key。完整 provider 示例可从项目 examples/models.example.json 获取。

06

其它程序怎样调用 API

本机鉴权的文本协作服务，地址为 http://127.0.0.1:8792 。

所有请求带 Authorization: Bearer 本机令牌。令牌保存在自己的 service.env，客户端从本机文件或环境读取，不写入 Issue。服务仅绑定本机，拒绝浏览器 Origin；本指南不会直接调用服务。

接口作用
GET /health检查服务与模式可用性。
GET /v1/models取得已登记的 provider、型号和 effort，不返回密钥。
POST /v1/respond请求 prompt 与 models，返回 mode、model、text 和 collaboration_calls。
Python 客户端 · 其它 API 模式（使用标准库）
import json, os, urllib.request
payload = {
    "prompt": "请给出这个方案的改进建议。",
    "models": {
        "mode": "api",
        "primary": {"provider": "other", "model": "OTHER_MODEL", "effort": "medium"}
    }
}
request = urllib.request.Request(
    "http://127.0.0.1:8792/v1/respond",
    data=json.dumps(payload, ensure_ascii=False).encode("utf-8"),
    headers={
        "Authorization": "Bearer " + os.environ["CODEX_COLLABORATION_TOKEN"],
        "Content-Type": "application/json"
    },
    method="POST"
)
with urllib.request.urlopen(request, timeout=900) as response:
    result = json.load(response)
print(result["text"])

先在自己的终端加载 service.env，让客户端继承本机令牌。上面会实际调用模型，型号需换成已登记的真实值；服务不会自动重试付费请求。

HTTP 模式primarycollaborators
gpt登记的 kind:gpt provider（例如 openai）不填写
api登记的 kind:other provider不填写
gpt-led登记的 kind:gpt provider至少一个 kind:other 模型
HTTP · GPT 主导示例（替换准确型号）
{
  "prompt": "请咨询协作者审查方案，再由你综合最终建议。",
  "models": {
    "mode": "gpt-led",
    "primary": {
      "provider": "openai",
      "model": "gpt-YOUR_HTTP_MODEL",
      "effort": "high"
    },
    "collaborators": [
      {
        "provider": "other",
        "model": "OTHER_MODEL",
        "effort": "medium"
      }
    ]
  }
}
HTTP 的 GPT primary 使用登记的 provider ID，如 openai；Issue 的 GPT primary 使用 codex。HTTP 是文本协作接口，不会修改仓库；仓库工作通过第 03 节的 Issue 派单协议执行。
07

本机文件与常见问题

运行目录独立于源码；保留数据库、会话和成果。

文件用途
config.jsonowner、host_id、记录仓库及绝对路径。
models.jsonprovider、地址、型号、协议与思考参数映射。
service.env本机令牌与模型密钥；仅本机维护。
state/mvp2.sqlite3领取去重、会话绑定和发布进度。
workspaces/仓库ID/request_id/每个任务的独立本地成果，实际路径见工作台。
state/runs/request_id/执行输出与诊断。
情况处理方法
工作台打不开确认本机运行环境和工作台进程已启动，前端已构建，8791 未被其它进程占用。
一直显示监听进程运行中监听运行不代表模型正在执行。顶部“当前运行状态”显示有没有任务、上次完成 GitHub 检查的时间和未领取原因；页面刷新时间仅代表读取本机记录。
Issue 没被领取先看工作台“未领取的 Issue”的原因，再核对标题前缀、唯一未编辑的 owner 授权评论、host_id 和目标基线；仓库需开启 Issues。
其它模型未被领取模型名（包括大小写）和思考强度需精确匹配本机登记。不要把展示名称或其它服务的 max / xhigh 等强度直接套用。可从已鉴权的 GET /v1/models 读取登记值；配置更改后空闲时重启加载。
等待模型回复时没有输出当前任务显示第几轮、已用时间和最近活动；API 文件操作在执行阶段显示。回复到达后自动更新，等待时不显示模型内部推理。
旧对话不匹配使用回执完整 UUID，保持同一机器、目标仓库与后端；会话文件必须属于监听器用户。
stale_base默认分支已变化，重新读取基线，发布新 Issue、新 request_id 与新授权。
failed读取回执和诊断，核对已有文件；修复原因后创建新任务，不编辑旧授权。
执行结束仍 running查看发布阶段，可能在补做 push、PR 或回执；确认已完成执行的网络发布失败只补发布。
中断后停止接单执行或 commit 不确定时保留进程、文件及状态，先核对现场，不删除数据库或自动重放。
成功但无 PR检查回执是否说明“无文件变化”，没有改动不创建空 PR。
关闭浏览器不会停止监听器。重启电脑后需要重新启动进程，或由自己配置的进程管理器启动；WSL 停止、关机或休眠时不会继续执行。
