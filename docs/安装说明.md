# 首次安装：当前版本

每台电脑独立安装一次，配置自己的 GitHub 账号、唯一机器标识和私有目录。以下在 Linux / Ubuntu / WSL 的 Bash 终端执行；Windows 用户先进入 WSL。Python 3.11+、Git、GitHub CLI、已登录的 Codex CLI 是执行端前提；前端构建需 Node.js 22.12+ 和 npm。原生 Windows 与 macOS 执行端尚未验收。

## 1. 检查账号并获取 main

按照各工具的官方安装说明安装依赖，然后确认登录：

~~~bash
python3 --version
git --version
gh auth login
gh api user --jq .login
codex login
codex --version
git clone https://github.com/xiangshui001/chat-codex_cli.git
cd chat-codex_cli
~~~

Chat 的 GitHub 连接与本机 gh 是两套凭据。Issue、评论和执行端账号必须是同一 owner，且两端能访问任务仓库。

## 2. 安装到仓库外的私有目录

下面的运行目录是通用默认值，可自行换成绝对路径。保留这个路径，后续终端需使用同一个值。

~~~bash
project_src="$(pwd)"
run_dir="$HOME/.local/share/chat-codex"
python3 -m venv "$run_dir/venv"
"$run_dir/venv/bin/python" -m pip install "$project_src/codex-github-local-v2"
~~~

新安装只提供当前四个命令。旧版本用户使用新虚拟环境和新运行目录；旧监听器空闲后停用，旧数据留在原目录。

## 3. 创建本机配置

先输入独一无二的机器标识。`desktop` 只是示例，多台电脑不能共用同一标识。以下生成初始配置、空模型表和随机本机 API 令牌；已有文件会拒绝覆盖。

~~~bash
account_owner="$(gh api user --jq .login)"
read -r -p "机器标识（如 desktop、laptop）： " machine_id
python3 - "$run_dir" "$account_owner" "$machine_id" <<'PY'
import json, os, re, secrets, sys
from pathlib import Path
root = Path(sys.argv[1]).expanduser().resolve()
owner, host = sys.argv[2].lower(), sys.argv[3]
if not re.fullmatch(r"[A-Za-z0-9][A-Za-z0-9-]{0,38}", owner):
    raise SystemExit("账号格式不正确")
if not re.fullmatch(r"[A-Za-z0-9][A-Za-z0-9_-]{0,63}", host):
    raise SystemExit("机器标识使用字母、数字、下划线或短横线，最长 64 位")
root.mkdir(parents=True, exist_ok=True, mode=0o700)
config = {
    "owner": owner, "host_id": host, "hub_repo": owner + "/codex-cli",
    "workspace_root": str(root / "workspaces"),
    "state_dir": str(root / "state"),
    "models_file": str(root / "models.json"),
    "poll_seconds": 60, "timeout_seconds": 10800, "max_parallel_tasks": 3
}
files = {
    "config.json": json.dumps(config, ensure_ascii=False, indent=2) + "\n",
    "models.json": '{"providers": {}}\n',
    "service.env": "CODEX_COLLABORATION_TOKEN=" + secrets.token_urlsafe(48) + "\n"
}
if any((root / name).exists() for name in files):
    raise SystemExit("已有配置，请保留并手工核对；没有覆盖文件")
for name, content in files.items():
    fd = os.open(root / name, os.O_WRONLY | os.O_CREAT | os.O_EXCL, 0o600)
    with os.fdopen(fd, "w", encoding="utf-8") as stream:
        stream.write(content)
print("配置已保存到", root, "；令牌保存在私有 service.env 中")
PY
~~~

初始 `hub_repo` 为 `你的账号/codex-cli`。要从记录仓库派单，先在 GitHub 建立这个仓库（可私有，需开启 Issues）；也可把配置改成本人已有的记录仓库。仅从目标仓库派单时无需新建它。不要公开 `service.env`、真实配置和运行目录。

只用 GPT CLI 时空模型表就可使用。其它模型按[模型配置协议](V2-MVP2.md#三种模型模式)登记；接口和型号替换为服务商真实值，密钥变量在 `service.env` 填写。该文件按 Bash 赋值语法书写，特殊字符用正确引号，并只读取自己维护的本机文件。

## 4. 检查发现并启动监听器

~~~bash
run_dir="$HOME/.local/share/chat-codex"
set -a
. "$run_dir/service.env"
set +a
"$run_dir/venv/bin/codex-github-local-v2" --config "$run_dir/config.json" --list-repos
"$run_dir/venv/bin/codex-github-local-v2" --config "$run_dir/config.json"
~~~

确认列表包含工作仓库。程序每轮分页扫描本人拥有且凭据可访问的仓库，排除归档、禁用或未开启 Issues 的仓库；新目标需有初始提交。这个终端持续监听，一次只执行一个任务。

## 5. 构建并打开工作台

另开一个终端，进入同一源码目录：

~~~bash
cd web/app
npm ci
npm run build
run_dir="$HOME/.local/share/chat-codex"
"$run_dir/venv/bin/codex-github-local-v2-workbench" \
  --config "$run_dir/config.json" --dist "$(pwd)/dist" --port 8791
~~~

打开 http://127.0.0.1:8791/ 。默认读取最新任务；工作台只读，浏览器关闭不会停止监听器。

## 6. 按需启动模型 HTTP API

Issue 的 GPT 主导模式使用任务专属 MCP，不需要额外启动 HTTP 服务。其它程序要调用文本协作接口时，另开终端：

~~~bash
run_dir="$HOME/.local/share/chat-codex"
set -a
. "$run_dir/service.env"
set +a
"$run_dir/venv/bin/codex-github-local-v2-model-api" \
  --models-file "$run_dir/models.json" --port 8792
~~~

请求带 `Authorization: Bearer <service.env 中的本机令牌>`。HTTP 的 GPT 模式需要登记 `kind: gpt` 的 OpenAI provider 和独立 API key；Codex CLI 登录不能代替该 key。完整请求见[API 协议](V2-MVP2.md#本机-http-api)。

## 7. 开始派单与持续运行

下载[HTML 指南](使用指南.html)，填自己的 owner、host_id、目标仓库、对话和模型选择，复制生成指令给已连接 GitHub 的 Chat。或按[Chat 协作手册](Chat协作手册.md)手动创建 Issue 和唯一授权评论。

确认一次小任务成功后，可自行用 systemd 等本机进程管理器维护监听器和工作台。项目不自动安装开机服务；系统、WSL 或进程停止时不会继续执行。重启配置或密钥前先等监听器空闲，避免中断任务。
