# Ubuntu / WSL 常见环境问题

- Windows 已登录网页不等于 Ubuntu 已保存 Codex CLI 或 GitHub CLI 登录；分别检查 `codex login status` 和 `gh api user --jq .login`。
- Windows 代理的 localhost 地址能否从 WSL 到达，取决于本机 WSL 网络设置。原环境验证过某个地址，不代表其他机器相同。先验证连接，再设置代理；不复制其他机器的 .wslconfig。
- 若系统找不到 bubblewrap，而启动提示明确说使用 bundled bubblewrap，这条警告本身不证明沙箱启动失败；继续看实际命令结果。
- 曾出现沙箱内代理不可达、单次批准沙箱外 `git ls-remote origin refs/heads/main` 后成功。该命令只查询引用；不能据此断言所有网络或所有命令都已获准，也无需因此整体关闭沙箱。
- 组合命令以分号串联时，末项退出码会成为整体退出码。一例中所有文档读取成功，但末项 `command -v uv` 未找到，所以整体为 1。逐项看退出状态，不把文档读取判成失败。
- `command -v` 找不到只证明当前 PATH 未找到；不能据此断言整台机器未安装。PATH 中有 Windows npm 也不证明 Ubuntu 的 Node 运行环境已准备好。
- 新克隆没有 .venv 很常见。依据项目开发文档和具体任务建立环境；项目使用 venv + pip 时不必另外安装 uv。只读核查不等于实际回归测试。
