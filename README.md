# chat-codex_cli

Chat 通过 GitHub Issue 发布授权任务，本机 Ubuntu / WSL 执行、保留成果、回写 Issue 并提交草稿 PR。当前入口为 **MVP-2（V2 0.1.0）**，支持新/旧对话、三种模型模式和账号内 `desktop` 路由；MVP-1 与 V1 保留。

## 从这里开始

- [用户使用手册](docs/用户使用手册.md)：安装、启动、打开工作台与查看成果。
- [Chat 协作手册](docs/Chat协作手册.md)：给 Chat 的派单协议与操作边界。
- [MVP-2 配置与协议](docs/V2-MVP2.md)：对话续接、GPT / 其它 API / GPT 主导、Host 路由和 PR 交付。
- [MVP-1 配置与协议](docs/V2-MVP1.md)：保留的账号仓库发现与仅本地成果模式。
- [工作台说明](docs/MVP1-WORKBENCH.md)：真实时间线、命令输出、文件变化、退出码与回执。

工作台服务启动后打开 **http://127.0.0.1:8791/**。开发服务器 5173 也默认进入真实工作台，需要同时运行 8791 的后端。历史演示必须显式访问 `?view=demo`，不会在真实连接失败时自动出现。

## 当前能力与限制

单用户执行端发现凭据可见的本人仓库；新仓库有初始提交后可派单，不需逐个登记。Issue 可发布在目标仓库或配置的本机记录仓库，必须精确匹配 `host_id`，例如 `desktop`。授权通过后按需克隆，每次只执行一个任务，SQLite 防重复执行。Chat 和执行端 GitHub 权限分别配置。

MVP-2 可新建或续接明确 UUID 的本机对话；GPT 经已登录 Codex CLI 执行，其它模型经本机登记的 OpenAI 兼容 API 执行，GPT 主导模式提供外部模型咨询工具。型号和思考强度随任务选择，接口与密钥只在本机配置。另提供有本机令牌保护的 HTTP 文本协作 API。

成果留在本机独立目录；文件检查通过后提交专用分支、推送、创建**草稿 PR**并回写原 Issue，合并仍由人工决定。工作台只读。发布网络失败可只补做发布；执行中断或不确定任务需人工核对，不自动重放。完整断电恢复、取消、重跑与容器隔离不在本轮范围。
